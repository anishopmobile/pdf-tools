# راهنمای عملی PDF Tools برای ویندوز — نسخه ۱.۰.۰

**زمان بررسی مخزن: ۲۰ اکتبر ۲۰۲۶.** این راهنما برای فایل‌های موجود در بسته سورس همین پروژه نوشته شده است. هنگام بررسی، مخزن عمومی `anishopmobile/pdf-tools` **کاملاً خالی** بود و نه فایل داشت، نه Commit اولیه، نه Release و نه اجرای GitHub Actions. در محیط ساخت این بسته، لینوکس اجرا شده؛ بنابراین **هیچ EXE یا Setup ویندوزی تولید، نصب یا روی ویندوز آزمایش نشده است.** تست‌های هسته روی لینوکس انجام شده‌اند، اما تست رابط PySide6 به دلیل نبود این کتابخانه اجرا نشده است. فایل‌های زیر در بسته سورسی که همراه پاسخ تحویل داده می‌شود موجودند؛ هنوز در مخزن GitHub نیستند. دستورهای این راهنما تا زمانی که سورس به GitHub منتقل نشده، باید بر اساس بسته سورس تحویلی اجرا شوند.

## ۱. وضعیت مخزن و نسخه پروژه

- مخزن مقصد: **https://github.com/anishopmobile/pdf-tools**
- شاخه پیش‌فرض مخزن: `main`؛ **بدون Commit اولیه** در زمان بررسی. کد تحویلی به‌صورت محلی در شاخه `main` ایجاد شده اما **Commit یا Push نشده است** (تا پیش از تأیید ساخت و اجرای واقعی ویندوز و نصاب، طبق معیار پذیرش).
- Hash نهایی Commit: **وجود ندارد**. لینک Commit نهایی: **وجود ندارد**.
- ورودی اجرای برنامه: `pdf_tools/__main__.py`؛ پردازش: `pdf_tools/core.py`؛ رابط: `pdf_tools/gui.py`؛ نسخه: `pdf_tools/__init__.py` با مقدار `1.0.0`.
- تست هسته: `tests/test_core.py`؛ تست رابط: `tests/test_gui.py`؛ تنظیم pytest: `pyproject.toml`.
- فایل Build ویندوز: `scripts/build_windows.ps1`؛ فایل نصاب: `installer/PDFTools.iss` و `scripts/build_installer.ps1`؛ تنظیم GitHub Actions: `.github/workflows/windows.yml`؛ آیکون: `assets/pdf-tools.ico`؛ اطلاعات نسخه: `packaging/version_info.txt`.

## ۲. دریافت سورس پروژه

**وضعیت کنونی:** به علت خالی بودن مخزن GitHub، روش «Code → Download ZIP» و `git clone` فعلاً سورس این برنامه را در اختیارتان نمی‌گذارند. ابتدا بسته `pdf-tools-source.zip` که همراه این پاسخ تحویل داده شده را بگیرید و از حالت ZIP خارج کنید. برای ساخت، وارد پوشه‌ای شوید که `requirements.txt`، `pdf_tools` و `scripts` در آن قرار دارند. هر محل مناسبی مانند زیرپوشه Documents قابل استفاده است. مسیرهای زیر صرفاً **مثال مسیر انتخابی شما** هستند، نه محل موجود در مخزن.

**روش ZIP از GitHub (پس از Push موفق):**

۱. صفحه https://github.com/anishopmobile/pdf-tools را باز کنید. ۲. گزینه سبز **Code** را بزنید. ۳. **Download ZIP** را بزنید. ۴. در File Explorer روی ZIP راست‌کلیک کنید و **Extract All** را انتخاب کنید. ۵. پوشه استخراج‌شده `pdf-tools-main` را باز کنید و مطمئن شوید `scripts/build_windows.ps1` آنجا موجود است. ۶. برای بازکردن PowerShell در این پوشه، روی نوار آدرس File Explorer کلیک کنید و `powershell` تایپ کنید.

**روش Git (پس از Push موفق):**

۱. [Git for Windows](https://git-scm.com/download/win) را نصب کنید. ۲. **PowerShell** را باز کنید. ۳. به محل دلخواه (مثلاً Downloads) بروید و Clone کنید:

```powershell
cd "$HOME\Downloads"
git clone https://github.com/anishopmobile/pdf-tools.git
cd .\pdf-tools
Get-ChildItem
```

نتیجه مورد انتظار پس از انتشار: فایل `requirements.txt` در خروجی `Get-ChildItem` دیده شود. **اکنون Clone یک مخزن خالی، سورس برنامه را دریافت نخواهد کرد.**

برای گذاشتن سورس تحویلی در مخزن خالی از طریق ویندوز (پس از آماده‌شدن برای تأیید روی ویندوز)، در PowerShell این ترتیب را اجرا کنید:

```powershell
cd "$HOME\Downloads"
git clone https://github.com/anishopmobile/pdf-tools.git
Expand-Archive -Path '.\pdf-tools-source.zip' -DestinationPath '.\pdf-tools' -Force
cd .\pdf-tools
Get-ChildItem -Force
```

دستورها فرض می‌کنند **فایل ZIP تحویلی را خودتان در Downloads گذاشته‌اید**؛ اگر در محل دیگری قرار گرفته، آدرس واقعی آن را در `-Path` بنویسید. محتویات ZIP در ریشه پوشه قرار دارند؛ `.git` پوشه Cloneشده نباید حذف شود. در این مرحله هنوز `git add` یا `git commit` نکنید؛ اول تست و Build و نصب واقعی را بررسی کنید.

**برای استفاده عادی از نسخه منتشرشده، اصلاً نیازی به دانلود سورس، Git یا Python ندارید**: فقط Setup قابل‌اعتماد را دریافت و نصب می‌کنید.

## ۳. آیا نسخه آماده وجود دارد؟

در لحظه بررسی، **GitHub Releases خالی بود**، هیچ اجرای GitHub Actions / Artifact ثبت نشده بود، و مخزن فایل Build نداشت. بنابراین لینک معتبر دانلود EXE/Setup از GitHub **هنوز وجود ندارد**. پس از اولین Push موفق و اجرای Workflow، در صفحه **Actions**، اجرای سبزرنگ `Windows tests and installer` را باز کنید. در بخش **Artifacts** باید `PDFTools-Windows-Setup` (حاوی `PDFTools-Setup.exe`) و `PDFTools-Windows-portable` (پوشه برنامه به‌صورت ZIP) و `PDFTools-Windows-Test-Results` ظاهر شوند، **فقط اگر Build و تست‌ها واقعاً موفق شوند**. نتایج Workflow را پیش از دانلود بررسی کنید. منتشرکردن فایل در **Releases** یک کار جداگانه است و در این پروژه به‌صورت خودکار انجام نمی‌شود.

**سه اصطلاح مهم:** سورس = کد و اسکریپت‌های سازنده؛ EXE = فایل اجرایی `PDFTools.exe` به همراه DLLهای پوشه `dist/PDFTools/` (به‌تنهایی قابل جابه‌جایی نیست)؛ Setup = فایل `PDFTools-Setup.exe` که فایل‌ها را نصب می‌کند و میانبر و Uninstaller می‌سازد. برای کاربر عادی **Setup** بهترین گزینه است. ZIP نسخه پرتابل باید کامل استخراج شود؛ فقط EXE را جدا نکنید.

## ۴. ساخت خروجی اجرایی ویندوز از سورس

**پیش‌نیاز:** ویندوز ۱۰/۱۱ نسخه ۶۴بیتی، اینترنت برای اولین نصب ابزارهای ساخت، Python 3.12 و PowerShell. از https://www.python.org/downloads/windows/ نصاب ۶۴بیتی Python 3.12 را دریافت و نصب کنید؛ گزینه نصب `py launcher` را نگه دارید. می‌توانید از **Terminal** ویندوز و تب PowerShell استفاده کنید. در PowerShell، در **ریشه سورس** (محلی که `requirements-build.txt` دیده می‌شود) این فرمان‌ها را اجرا کنید:

```powershell
py -3.12 --version
Get-Location
.\scripts\build_windows.ps1
```

فرمان اول باید چیزی شبیه `Python 3.12.x` نشان دهد؛ دومی محل واقعی پروژه را نشان می‌دهد؛ سومی به‌ترتیب `.venv` را می‌سازد، نیازمندی‌های ثابت `requirements-build.txt` را با pip نصب می‌کند، `pytest` و `compileall` را اجرا می‌کند، سپس با PyInstaller بسته ویندوز را می‌سازد. اگر تستی شکست بخورد، اسکریپت قبل از Build متوقف می‌شود. نسخه فعلی از **one-folder** استفاده می‌کند تا DLLها و افزونه‌های Qt کنار EXE باقی بمانند و عیب‌یابی ساده‌تر شود. اجرای این اسکریپت در اولین مرتبه نیازمند اینترنت است؛ خود برنامه بعد از Build بدون اینترنت اجرا می‌شود.

خروجی مورد انتظار پس از موفقیت واقعی:

```text
dist\PDFTools\PDFTools.exe
dist\PDFTools\_internal\...   (DLLها، افزونه‌های Qt و کتابخانه‌های موردنیاز)
```

مسیر `_internal` وابسته به نسخه PyInstaller است و دقیقاً تنها بعد از Build قابل تأیید خواهد بود. برای اجرای برنامه:

```powershell
.\dist\PDFTools\PDFTools.exe
```

پنجره‌ای با عنوان `PDF Tools` و دو گزینه `JPG to PDF` و `Merge PDF` باید باز شود. هر دو قابلیت را با داده آزمایشی تست کنید. برای بررسی کتابخانه‌ها، **تمام پوشه** `dist\PDFTools` را به یک رایانه ویندوزی تمیز منتقل و همان EXE را اجرا کنید (بدون نصب Python). این آزمون در محیط فعلی انجام نشده است.

اگر PowerShell اجرای فایل `.ps1` را مسدود کرد، ابتدا سیاست سازمان را بررسی کنید. به‌جای تغییر سراسری تنظیمات می‌توانید **فقط برای همین نشست** و با اختیار خودتان چنین اجرا کنید:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1
```

اگر `py -3.12` پیدا نشد، Python 3.12 و Python Launcher را نصب یا ترمیم کنید؛ **نسخه دیگری را بدون آزمون جایگزین نکنید**. اگر `pip` به اینترنت وصل نشد، اتصال/Proxy و فایروال را بررسی کنید. اگر تست GUI اجرا نشد یا PySide6 import error داد، نصب وابستگی‌های همین `requirements-build.txt` را بررسی کنید. اگر PyInstaller خطای DLL/Qt داد، خروجی ترمینال و فایل‌های زیر `build` را بررسی کرده و از همان معماری ۶۴بیتی Python استفاده کنید.

**اجرای تست‌ها به‌صورت جداگانه** از همان پوشه:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall -q pdf_tools tests
```

نتیجه معتبر یعنی خروجی pytest بدون `FAILED` و بدون `ERROR`. اگر `SKIPPED` دیدید، علت را جداگانه بررسی کنید؛ **تست GUI در Windows CI باید واقعاً اجرا شود**. وجود فایل EXE به‌تنهایی اثبات عملکرد صحیح نیست.

## ۵. ساخت فایل نصبی Setup

ابزار واقعی انتخاب‌شده **Inno Setup 6** است؛ تنظیمات نصاب از قبل در `installer/PDFTools.iss` نوشته شده و قابل تکرارند. Inno Setup را از https://jrsoftware.org/isinfo.php دریافت و نصب کنید. **بعد از** ساخت موفق EXE و بررسی کارکرد اولیه، در PowerShell ریشه پروژه بزنید:

```powershell
.\scripts\build_installer.ps1
```

اسکریپت ابتدا وجود `dist\PDFTools\PDFTools.exe` را بررسی می‌کند، سپس `ISCC.exe` مربوط به Inno Setup 6 را اجرا می‌کند. خروجی مورد انتظار **اگر Build موفق شود**:

```text
dist\installer\PDFTools-Setup.exe
```

نصاب با نام **PDF Tools** و نسخه **1.0.0**، در حالت معمول برای کاربر جاری داخل `%LOCALAPPDATA%\Programs\PDFTools` نصب می‌شود؛ مجوز Administrator لازم ندارد؛ پوشه نصب قابل تغییر است؛ میانبر Start Menu ایجاد می‌شود؛ ساخت Desktop shortcut اختیاری است؛ و Uninstaller در Windows Settings > Apps ثبت می‌شود. امضای دیجیتال برای تولید/اجرای نصاب شرط فنی اجباری نیست، ولی فایل امضانشده ممکن است SmartScreen نشان دهد. تا زمانی که آن را خودتان تولید یا منبع آن را با SHA-256 تأیید نکرده‌اید، از عبور بی‌بررسی از هشدارها خودداری کنید.

در صورت خطای `Inno Setup 6`، بررسی کنید `ISCC.exe` در Program Files نصب شده باشد. در صورت خطای «Missing expected EXE»، مرحله ۴ را با موفقیت تکمیل کنید. در صورت خطای دسترسی، خروجی را در مسیری که اجازه نوشتن دارید Build کنید.

## ۶. نصب، اجرای نخست و حذف

۱. از **Artifact تأییدشده CI** یا خروجی Build روی ویندوز خودتان فایل `PDFTools-Setup.exe` را دریافت کنید؛ در وضعیت کنونی لینکی از GitHub وجود ندارد. ۲. برای اطمینان از نام و اثرانگشت فایل، در PowerShell پوشه فایل واقعی را انتخاب کنید و اجرا کنید:

```powershell
Get-Item .\PDFTools-Setup.exe | Select-Object Name,Length,LastWriteTime
Get-FileHash .\PDFTools-Setup.exe -Algorithm SHA256
```

۳. Hash را با مقداری که سازنده قابل‌اعتماد ارائه کرده مقایسه کنید؛ اگر شناسه قابل‌اعتماد ندارید، ادعای اصالت نکنید. ۴. روی Setup دوبارکلیک کنید و در صورت پیام امنیتی ویندوز، فقط در صورت تأیید منبع تصمیم به ادامه بگیرید. ۵. مسیر نصب (پیش‌فرض مخصوص کاربر جاری) را بررسی کنید. ۶. گزینه میانبر دسکتاپ را در صورت تمایل انتخاب کنید. ۷. **Install** و سپس **Finish** را بزنید. ۸. از منوی Start عبارت `PDF Tools` را پیدا و اجرا کنید. ۹. در پایان در Windows Settings > Apps > Installed apps، **PDF Tools** را پیدا کرده و برای حذف **Uninstall** را انتخاب کنید. فایل‌های شخصی PDF/JPG در پوشه‌های خودتان حذف نمی‌شوند.

**بررسی نصب روی ویندوز در زمان نوشتن این راهنما هنوز انجام نشده**؛ تست CI تنظیم شده اما هنوز اجرا نشده است.

## ۷. آموزش دو قابلیت با مثال

### ۷.۱. JPG to PDF

۱. PDF Tools را اجرا و کارت **JPG to PDF** را باز کنید. ۲. از File Explorer چند تصویر `.jpg` یا `.jpeg` را به ناحیه آبی بکشید؛ یا **Add Images** را بزنید و چند فایل را هم‌زمان انتخاب کنید. ۳. تعداد و مسیر تصاویر را بالای فهرست ببینید. ۴. با کشیدن ردیف‌های فهرست، ترتیب را تنظیم کنید؛ با **Remove Selected** مورد اشتباه را حذف کنید. ۵. **Convert to PDF** را بزنید. هنگام پردازش درصد Progress و نام وضعیت نمایش داده می‌شود؛ **Cancel** در نقاط امن پردازش کار می‌کند. ۶. پس از اتمام، مسیر نهایی زیر Status نشان داده می‌شود؛ **Open PDF** یا **Open Output Folder** را بزنید. ۷. ترتیب و تعداد صفحات را در PDF viewer بررسی کنید.

**مثال:** در یک پوشه سه تصویر `01.jpg`، `02.jpeg` و `03.jpg` دارید. اگر آن‌ها به همین ترتیب در فهرست باشند، `converted_images.pdf` با سه صفحه و همین ترتیب در **همان پوشه تصاویر** ذخیره می‌شود. اگر فایل `converted_images.pdf` قبلاً موجود باشد، نسخه جدید `converted_images_1.pdf` و سپس شماره‌های بعدی تولید می‌شوند؛ فایل قدیمی دست‌نخورده می‌ماند. اگر تصاویر در چند زیرپوشه باشند، پوشه والد مشترک مناسب انتخاب می‌شود. اگر پوشه مشترک قابل‌استفاده نباشد، برنامه پوشه مقصد را از شما می‌پرسد. تصویر غیر JPEG یا پوشه رهاشده با پیام رد می‌شود.

### ۷.۲. Merge PDF

۱. در صفحه اصلی کارت **Merge PDF** را باز کنید. ۲. **Select Folder** را بزنید؛ پوشه‌ای که PDFها مستقیماً داخل آن هستند انتخاب کنید (نه زیرپوشه‌ها). ۳. فهرست و تعداد PDFهای قابل‌خواندن را ببینید. ترتیب اولیه طبیعی است، اما می‌توانید ردیف‌ها را بکشید و مرتب کنید. ۴. حداقل دو فایل نیاز است؛ **Merge PDFs** را بزنید. ۵. بعد از موفقیت، تعداد فایل و مجموع صفحات و مسیر خروجی نمایش داده می‌شود. ۶. PDF نهایی را با **Open PDF** باز و صفحات را کنترل کنید. ۷. برای کار جدید **New Operation** را بزنید.

**مثال:** فایل‌های `file1.pdf` دو صفحه، `file2.pdf` سه صفحه و `file3.pdf` یک صفحه دارند. در ترتیب پیش‌فرض و بدون تغییر، `merged_document.pdf` شامل ۶ صفحه است: اول دو صفحه `file1.pdf`، سپس سه صفحه `file2.pdf`، و در آخر یک صفحه `file3.pdf`. اگر `merged_document.pdf` قبلاً موجود باشد، خروجی تازه `merged_document_1.pdf` نام می‌گیرد؛ خروجی‌های قبلی به‌صورت پیش‌فرض دوباره در فهرست ورودی قرار نمی‌گیرند. فایل رمزدار نیازمند گذرواژه یا PDF خراب ممکن است با پیام رد شود؛ برای اسناد امضاشده یا فرم‌های پیچیده، محدودیت‌های README را بخوانید.

## ۹. به‌روزرسانی نسخه‌های آینده

**کاربر عادی Setup:** فقط Setup نسخه جدید از منبع تأییدشده را اجرا می‌کند؛ نیازی به Git، Python، PyInstaller یا Inno Setup ندارد. قبل از نصب جدید، برنامه فعلی را ببندید. اطلاعات نسخه را از UI پایین صفحه و بخش Installed apps ببینید؛ برای اصالت فایل از SHA-256 کمک بگیرید.

**توسعه‌دهنده با Clone:** بعد از انتشار اولیه، PowerShell را در پوشه Clone باز کنید و اجرا کنید:

```powershell
git status
git pull --ff-only origin main
.\scripts\build_windows.ps1
.\scripts\build_installer.ps1
```

پیش از `git pull` باید تغییرات محلیِ ذخیره‌نشده را بررسی کنید؛ این دستور با `--ff-only` تاریخچه را بازنویسی نمی‌کند. تست‌ها داخل `build_windows.ps1` اجرا می‌شوند. `build_installer.ps1` به Inno Setup نیاز دارد. نسخه را در `pdf_tools/__init__.py`، `packaging/version_info.txt` و `installer/PDFTools.iss` هماهنگ تغییر دهید؛ نسخه Windows EXE و Setup باید برابر باشند. **این هماهنگ‌سازی فعلاً خودکار نیست.** پس از build، تست EXE و نصب/حذف با فایل‌های آزمایشی را روی ویندوز تکرار کنید و سپس فایل Setup جدید را با همان منبع منتشر کنید.

### ثبت Git فقط پس از پذیرش واقعی

پس از تکمیل آزمایش‌های بالا و اطمینان از اینکه هیچ فایل شخصی یا فایل Build وارد Git نشده، در همان پوشه Clone شده PowerShell:

```powershell
git status --short
git add .gitignore .github/workflows/windows.yml README.md docs/WINDOWS_GUIDE_FA.md docs/MANUAL_TESTS_FA.md assets/pdf-tools.ico installer/PDFTools.iss packaging/version_info.txt pdf_tools/__init__.py pdf_tools/__main__.py pdf_tools/core.py pdf_tools/gui.py pyproject.toml requirements.txt requirements-build.txt scripts/build_windows.ps1 scripts/build_installer.ps1 tests/test_core.py tests/test_gui.py
git diff --cached --stat
git diff --cached --check
git commit -m "feat: add JPG to PDF and PDF merge desktop tools"
git rev-parse HEAD
git push origin main
```

اگر تست یا نصب شکست خورد **Commit نکنید**؛ مشکل را اصلاح و تست‌ها را تکرار کنید. دستور `git add` فقط فایل‌های مشخص این پروژه را Stage می‌کند. `git push` فقط پس از موفقیت Commit، داشتن مجوز و بررسی شرایط مخزن انجام شود. پس از Push موفق، صفحه GitHub را Refresh و Workflow را از تب Actions بررسی کنید؛ پس از دریافت نتیجه سبز واقعی، Artifact Setup را دانلود کنید. در این وضعیت هنوز Hash Commit یا لینک Release برای درج در راهنما وجود ندارد.
